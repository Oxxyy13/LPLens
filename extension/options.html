✓

Privacy by construction

The extension only asks for what it needs.

Your saved wallet addresses, settings, locally hidden-position choices, immutable event-history cache, most recent rendered portfolio view, and sanitized most-recent diagnostic summary stay in chrome.storage.local. The saved portfolio view is used only to make the browser side panel appear immediately and is replaced after a successful refresh. The diagnostic summary contains no wallet, label, token, pool, position, key, endpoint, or raw error, and it leaves the browser only if you press Copy diagnostics. When you scan, LPLens sends the address and public-chain query data to the named RPC, price, and history services needed to return results. For a v4 position with later additions, the public transaction hashes are also sent to the chain's public Blockscout trace endpoint so principal and already-earned fees can be separated exactly. The LPLens service processes allowlisted Blockscout log filters; it does not store wallet addresses, filters, responses, or completed portfolio views.

There is no wallet connection, private key, or signing access. The beta service stores hashes of the access code and a random browser-installation identifier, plus first/last seen and daily relay-request totals. If the control below is on, it also stores anonymous daily scan totals by extension version, surface, outcome, coarse position-count and duration buckets, and allowlisted per-chain error categories. Those scan totals are not linked to an access code, installation, wallet, token, pool, or position. Raw error messages are never sent. The service does not store IP addresses or fingerprint the browser. Optional page access is off at install and disclosed immediately below.

On-page overlays

Bring position context onto the protocol page where you use it.

LPLens has no access to any web page when installed. Each site below is independently optional. On Uniswap it reads the position-page URL; on the positions list it reads position links and the first line of visible row text to discover and label positions. On ProjectX it runs only on www.prjx.com/portfolio and uses the active overlay wallet you select in LPLens; it does not read ProjectX page content or the connected wallet. On Dexscreener it reads the chain and pool identifier in a pair-page URL, then checks that same active wallet for a matching position. The service worker sends those two route values, without the wallet address, to api.dexscreener.com to match the pair's token orientation. It never reads balances, forms, signing prompts, connected-wallet state, or the wallet provider. Turning a site off tells any open LPLens overlay to shut down, removes that permission, and unregisters future injection. The service worker also re-checks Dexscreener permission before returning position data or measuring chart geometry.

LOCAL-ONLY EXPERIMENT: This build tests a chart-aligned range. For one measurement at a time, the service worker gives a narrowly scoped function in Dexscreener's MAIN world anonymous LP low, current, and high range numbers. It does not provide a wallet address, token ID, PnL, access key, custom endpoint, or provider key. The function reads chart mode, plot geometry, and numeric price coordinates through Dexscreener's private TradingView interface. It does not read or call the wallet provider and does not create a chart drawing, change autoscale, move the visible range, or otherwise alter chart state. Dexscreener page code could technically observe the range numbers while the function runs. LPLens's persistent isolated content script validates the returned numbers and draws its own overlay. The private chart interface is brittle, so alignment may stop working after a Dexscreener change. This experiment is blocked from release packaging.

Optional. Leave this closed unless you have a reason to change endpoints or add a key. Licensed builds include access to the LPLens Blockscout Pro relay on Ethereum, Base, Arbitrum and Polygon, so nothing here is required. An Etherscan V2 key is an optional direct alternative, and it is still the only verified way to get complete Polygon history — polygon.blockscout.com silently misses positions below roughly tokenId 1.2M. Custom RPC URLs are for when a public endpoint rate-limits you.

Custom RPC endpoints

Leave blank to use the built-in public defaults. Your own Alchemy/Infura/dRPC URL is faster and more reliable. Alchemy's free tier still caps eth_getLogs at a 10-block range, so an Alchemy URL here does not replace a history source.

Etherscan V2 API key

Optional. Free key from etherscan.io/apis (Etherscan V2 is multichain). Faster than Blockscout on Ethereum, Arbitrum and Polygon. On Base, Etherscan's free tier refuses logs, so LPLens keeps using Blockscout there even with a key. Robinhood Chain's public Blockscout and RPC provide its history and v4 addition proofs without a user key.
