Privacy by construction

The extension only asks for what it needs.

Your saved wallet addresses and labels, separately selected active overlay wallet address, selected portfolio chains and refresh scope, locally hidden-position choices, overlay layout and chart-consent settings, immutable event-history cache, local current-position ID index, exact v4 ownership block checkpoint, bounded per-position refresh comparison samples, receipt-proven v3 replacement links, most recent rendered portfolio view, and sanitized most-recent diagnostic summary stay in chrome.storage.local. Refresh samples contain the public position identity, observation time, range state, position value, LP return, vs-holding result, cumulative token fees, marks, and cash-flow counters needed to compare two accepted refreshes. Replacement links contain public wallet, chain, manager, pool, position, transaction, block-hash, log-index, and event-amount proof facts. They are rechecked against the transaction receipt and canonical block before display. The refresh samples and replacement links are not sent in telemetry or used to fill missing current data. The current-position index and v4 checkpoint contain only public wallet, chain, protocol deployment, manager, position ID, direct or gauge custody, custodian contract, ownership, and block-checkpoint data. They make manual refreshes faster, are verified against live chain state before use, and are never used as accounting or price input. The saved portfolio view is used only to make the browser side panel appear immediately and is replaced after a successful refresh. The diagnostic summary contains no wallet, label, token, pool, position, key, endpoint, or raw error, and it leaves the browser only if you press Copy diagnostics. When you scan, LPLens sends the address and public-chain query data to the named RPC, price, and history services needed to return results. For a direct UP33 NFT, the public manager and token ID are sent directly to Robinhood Chain's public RPC for complete exact-token Transfer history. Returned Transfer addresses stay in extension context and are not sent to LPLens or its Worker. For a v4 position with later additions, the public transaction hashes are also sent to the chain's public Blockscout trace endpoint so principal and already-earned fees can be separated exactly. If Robinhood Chain's public RPC exhausts its addition-receipt retries, LPLens first requests the public transaction and log records from Robinhood Chain's public Blockscout v2 REST API using the public transaction hash. If those records are unavailable, LPLens sends chain id 4663 and the public transaction hash, together with the access key and random installation ID, to the authenticated LPLens Worker. The Worker requests the exact successful receipt from Blockscout Pro and returns it only when it contains the expected v4 PoolManager ModifyLiquidity event attributed to the configured PositionManager. It does not store the transaction hash or receipt body. The LPLens service also processes allowlisted Blockscout log filters; it does not store wallet addresses, filters, responses, or completed portfolio views.

Supported standard Uniswap position cards can show a Revert link. LPLens does not contact Revert unless you click it. The link contains only the public network and NFT ID needed to open that position. Revert Finance is a separate third-party site, and any wallet connection, approval, signature, or transaction happens there, not in LPLens. This link adds no Revert site permission to the extension.

There is no wallet connection, private key, or signing access. The beta service stores hashes of the access code and a random browser-installation identifier, plus first/last seen and daily relay-request totals. If the control below is on, it also stores anonymous daily scan totals by extension version, surface, outcome, coarse position-count and duration buckets, and allowlisted per-chain error categories. Those scan totals are not linked to an access code, installation, wallet, token, pool, or position. Raw error messages are never sent. The service does not store IP addresses or fingerprint the browser. Optional page access is off at install and disclosed immediately below.

U

On-page overlays

Bring position context onto the protocol page where you use it.

LPLens has no access to any web page when installed. Each site below is independently optional. On Uniswap it reads the position-page URL; on the positions list it reads position links and the first line of visible row text to discover and label positions. On ProjectX it runs only on www.prjx.com/portfolio and uses the active overlay wallet you select in LPLens; it does not read ProjectX page content or the connected wallet. On UP33 it runs only on up33.xyz/liquidity and its subpages. On the exact liquidity list it reads only each concentrated-position row's public data-flow="cl-<NFT ID>" attribute, matching visible #ID, and row geometry so local PnL cards can align with matching rows. When you activate a validated row, LPLens keeps that public NFT ID and click state in memory for up to five seconds while it associates a newly opened Manage drawer with the matching already-scanned position. Once matched, the selected public NFT ID remains in memory only until the drawer closes, the route or active wallet changes, or site access is revoked. Neither state is persisted, transmitted, or included in telemetry. Opening the validated drawer automatically starts a fresh public-chain UP33 scan for the active overlay wallet; completed custody proofs are not reused. A right-docked Manage drawer contributes only its visible boundary so the LPLens card stays beside it; LPLens does not read dialog contents. Expanded values are limited to allowlisted current amounts, range, fees and rewards, cash flow, capital additions, and performance fields from public on-chain data. Page-derived IDs are matched only against the active-wallet scan. It does not read UP33 connected-wallet state, balances, forms, transaction controls, signing prompts, the wallet provider, or other UP33 page content. Only a shortened wallet label and the display fields needed by the panel cross into the page script. UP33 v2 LP and liquidity-locker positions are not read. On Dexscreener it reads the chain and pool identifier in a pair-page URL, then checks that same active wallet for a matching position. The service worker sends those two route values, without the wallet address, to api.dexscreener.com to match the pair's token orientation. It never reads balances, forms, signing prompts, connected-wallet state, or the wallet provider. Turning a site off tells any open LPLens overlay to shut down, removes that permission, and unregisters future injection. The service worker re-checks Dexscreener permission and UP33 permission before returning position data and re-checks both Dexscreener permission and separate chart consent before measuring chart geometry.

Chart alignment disclosure: This is a separate opt-in. While a matching overlay is open, LPLens repeatedly runs a packaged, short-lived function in Dexscreener's MAIN world so the range follows chart movement and mode changes. Each call receives up to three unlabelled LP range values for low, current, and high, plus public pair-conversion values. The call receives no wallet address, token or position ID, PnL, access key, custom endpoint, or provider key directly. Unlabelled does not mean anonymous: the pool and bounds are public on-chain, so Dexscreener page code could correlate them with a specific position and owner while each call runs. The function reads the chart mode, the latest public chart close once per measurement, plot geometry, and numeric price coordinates. The close stays inside that short-lived MAIN-world call. Only validated chart mode, plot geometry, and numeric coordinates return to LPLens's isolated overlay for the drawing; the close is not returned. The returned result is not stored, logged, or transmitted over the network. The function does not read or call the wallet provider, read forms or signing prompts, or change the chart. If alignment is off or unavailable, LPLens uses its own exact on-chain range ruler.

Custom RPC endpoints

Leave blank to use the built-in public defaults. Your own Alchemy/Infura/dRPC URL is faster and more reliable. Alchemy's free tier still caps eth_getLogs at a 10-block range, so an Alchemy URL here does not replace a history source.

Etherscan V2 API key

Optional. Free key from etherscan.io/apis (Etherscan V2 is multichain). Faster than Blockscout on Ethereum, Arbitrum and Polygon. On Base, Etherscan's free tier refuses logs, so LPLens keeps using Blockscout there even with a key. Robinhood Chain's public Blockscout and RPC provide its history and v4 addition proofs without a user key.
